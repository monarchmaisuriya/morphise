Morphise reshapes Paseo's interface from settings forms, adds a status-aware sidebar, and gives you a kanban task board with reminders that bring you back to the right chat at the right time. Change something under Settings, Plugins, Morphise and it saves on its own; every connected Paseo app updates within a moment, without a reload.

## What you can change

Settings are split into tabs: Layouts, General, Sidebar, Chat, Messages, Pages, Look, Buttons, Commands, Prompts and Advanced (the whole profile as JSON).

- **Layouts:** keep several whole setups and switch between them in settings or from the Command Center ("Morphise layout: …"). Your 0.1 profile becomes the layout "Default".
- **Sidebar view:** a replacement for the workspace list. Pick "Morphise" in Paseo's Settings, Sidebar, Sidebar view (Morphise's settings remind you while Paseo still shows its own). It lists workspaces or chats.
  - Sort by status (the order is yours), last prompt, name, newest, latest status change or most changed lines, with pinned workspaces first.
  - Group by project, status, last used (Today, Yesterday, This week…), label, or not at all, with counts in the headers. Groups you fold stay folded on that device.
  - **Your groups** (Group by, "Your groups"): sort projects into groups you name, such as Work or Clients, shared by every app on the daemon. The folder button in the header adds a group. The group you used most recently (by its newest workspace) comes first, Ungrouped last; turn that off in Settings, Sidebar, Your groups to order groups yourself. Drag a project by its heading into, between or within groups, and, when you order them yourself, a group by its heading up or down (after a long press on a phone); a group's ⋯ menu renames it, moves it up or down (when you order them yourself), or deletes it (its projects go to Ungrouped; a group with projects asks you to confirm first); a project's ⋯ menu moves it to a group, starts a workspace in it, copies its path or removes it (see Setup and limits). Groups and projects take a colour (11 presets, or any colour from the "+" swatch: a hex code, or the colour wheel on desktop and web) and an icon (36, or any emoji or letters, drawn in the chosen colour; press the chosen icon again, or empty the text, to take it off) from "Colour and icon" in their menus, and a workspace a colour from "Set colour" in its own; colours show only in Morphise's view. A project's colour fills its letter tile and colours the folder icon and name of the project tag on its workspace rows; group and project headings keep the normal text colour (a group with a colour and no icon shows a small swatch). The look (text size, space between groups, indent, branch lines and their corners, chat row marks, bold group names, folder icons and background workspaces) is in Settings, Sidebar, Look on this device, kept per device; and the row height (Compact, Comfortable or Spacious) in Settings, Sidebar. Projects with no workspace are listed too, unless a filter is on; a project whose workspaces are all background ones (such as a workers project) stays hidden unless Show background is on. In the chat list, each workspace's chats sit under its project's group.
  - Each group shows 5 workspaces by default, then "Show more"; change the number in Settings, Sidebar.
  - Filter by status, project, hide done, only changed, or only pinned, from the Filter menu; active filters show as tags.
  - It looks like Paseo's own sidebar: a header with a borderless search first (it fills the row and never draws a box; its magnifier brightens while you type, and a clear button shows), then the tools in groups split by thin dividers: Dispatch and a new-group button (when grouped by your groups), the status filter menu (with "Needs me") and display options, and a Next button that opens the next workspace waiting for you; a Pinned section; project groups with letter tiles and a "+" for a new workspace in that project.
  - Two-line rows: the title, then a muted line with what needs you ("Waiting for your permission", "Failed"), "Working" and the latest chat, and the details you chose. Running work pulses, on the chat row itself when it is listed. "One line" is an option.
  - Everything Paseo's own rows offer that a plugin can reach: on hover Pin and Archive (press twice) and a ⋮ menu, also on right-click or long press, with Copy path, Copy branch name, Rename, Labels, Remind me, Add task, Open pull request and open a service; a hover card with changes, host, branch, folder, pull request, checks, services and labels.
  - The Display menu holds Group by and Sort by, with All sidebar settings pinned at its top; titles, rows, per-group counts, chats and what each row shows are in Settings, Sidebar.
  - Chats under a workspace: the latest 5 (changeable), then "Show more"; each chat's sub-agents under it, also the latest 5 (changeable or hidden); only the open chat or sub-agent is highlighted.
  - Shorten long groups with "Show more"; workspaces that need permission or failed always show.
  - Colours say what each row needs: needs permission amber, failed red, running white (pulsing), finished but unread green, done gray; uncommitted branches amber, unpushed commits blue, merged pull requests purple.
  - Mark a workspace done or unread yourself, set a reminder on it, add it to tasks, or select several for bulk actions (pin, mark done, label, archive).
  - Auto-archive (off by default) archives workspaces marked done some days ago, never a worktree with uncommitted, unpushed or unknown changes; it checks again just before archiving. Archiving a Paseo worktree deletes its folder, so files git ignores there (a local `.env`, build output) are deleted with it. Merged pull requests use Paseo's own "Archive merged PR workspaces" setting.
- **Workbench** (one row in Paseo's sidebar header): everything that needs you in one screen, with a list of views on the left that folds to icons.
  - **Activity** (after Activity by koinzhang, see NOTICE.md; on unless turned off in Settings, General, Activity): how agents were used, counted from Claude Code and Codex logs on the daemon's computer. Sessions, prompts, top provider and top model with the change on the week before; a daily heatmap of 52 weeks; agents created over 30 days by provider; the last 168 hours (sessions, prompts, skills or MCP); provider and project rankings; insights (active days, busiest day, longest streak, peak weekday, workspaces, coding share, multi-turn share, average session); and the most used skills, MCP tools and models. Filter by provider and workspace; with a workspace picked, its open terminals are listed with their last lines and a Close that asks first. The first look at a long history indexes it over several refreshes ("Indexing n of m chats"); the counts (numbers and tool names, no conversation text) are kept in Paseo's plugin cache. Other providers' chats count as sessions only; tool calls inside sub-agents are not counted.
  - **Agents** (after Better Paseo, see NOTICE.md): every agent on this host by status, as a list (the default: Waiting, To review, Running, Done, Archived, what needs you first) or as lanes that share the width, picked per device; empty lanes, and Archived until opened, fold to short headers. Cards show the fields you pick (16, with Minimal, Standard and Full presets; Plan is read while the agent runs or asks a permission and once more when it stops, since reading a finished agent's history makes Paseo start it again, so a finished card shows the plan only if it was seen working since the app loaded; opening a finished agent's details pane still reads its history), with Open, Archive, Allow and Deny (one press sends the allow the agent marks as its main choice, or Paseo's default when it marks none; the details pane lists every choice), Clear (a finished agent you read moves to Done on this device), and Stop and Rename through Paseo's command line. Filter by status, agent, label, project, workspace and last update, search (with "Search conversations", the button beside the box, kept per device and off by default, also inside Claude Code and Codex chats: the words must all be in one message, read from the chat's own log, never in a way that wakes a finished agent; matching cards show the excerpt; sub-agents' own conversations are not searched), sort nine ways, move with J/K and H/L. A details pane answers a permission, shows the error, first prompt, last reply, sub-agents, usage and activity, has a reply box and Bookmark answer, and can "Generate a title" with a short background agent (uses tokens; only when you ask).
  - **Tasks:** your task board, as columns or a list, with Today (reminders due and cards due) and Archived picked under Filter, Show.
  - **Bookmarks:** answers you kept with /bookmark.
- **Session stats** (after Harness Stats, see NOTICE.md; on unless turned off in Settings, Chat, Session stats): for each Claude Code or Codex chat, read from the chat's own log on the daemon's computer (counts only; nothing is stored or sent): turns, model steps, model and tool time, time to first token, output speed, total tokens, cache hit, uncached input, cache read and write, and output, history from before Morphise included; and under Tools (after Activity by koinzhang), prompts, skill calls, MCP calls (and failures), shell calls, file reads and writes, tools explored, and the skills and MCP tools used with when each was last used. A Stats button in each workspace's top bar (beside Remind me) shows the open chat's tokens and cache hit; its popover (420 wide) is a glance: total tokens and cache hit, a bar of where the tokens went with its two biggest parts named, turns, steps, first token and speed, model and tool time, and the three most used skills and MCP tools, with a chat picker when the workspace has several chats; the Stats panel (Command Center: "Open this chat's session stats") shows all of them, plus a bar and a table per turn (the last 200: start, duration, steps, tokens, cache hit, model and tool time) and, when the chat has sub-agents, each one's tokens, cache hit and turns; the Agents details pane has a Session section. They refresh every 2 s while on screen. Times come from the log's timestamps, so they are estimates. An optional strip under the message box (desktop and web, off by default) shows them in one line; it reads Paseo's page, so a Paseo update can hide it. Other providers' chats say "No stats".
- **Steps card:** a chat's plan as a card, in the chat where the agent posts it (or in the sidebar), that shows while it works and settles when it is done. Choose when it shows, how long "All done" stays, top or bottom, the open chat or every chat in the workspace, how many steps, hiding finished steps, starting folded and the progress bar, under Settings, Sidebar, Steps card.
- **Checks panel:** a workspace tab with the pull request's checks, review and conflicts, and "Ask the agent to fix".
- **Dispatch** (the two-cards button in the sidebar view's header, or the Command Center): start several agents at once, each in a new workspace. Pick the project, any model your providers offer, the mode, and worktree or project folder (remembered on each device), write or paste the prompts (a pasted list splits into one prompt per item), and start them all with ⌘↵. Each prompt then shows Starting, Started (with Open) or Failed (with Retry).
- **Chat** (rows from Chat Polish, see NOTICE.md): tool calls (MCP tools and plans included) as single rows with a verb, the command or file and a short detail, opening to the diff, output or input; the thoughts and calls between two replies merged into one row ("Edited 1 file and ran 2 commands"); code colours for commands, diffs and JSON; program icons, word-level diffs, folded long output, pictures (PNG, JPEG, GIF or WebP up to 12 MB), Copy, a Details tab, Show in Finder; folding rules by kind; errors and notices as rows; an opt-in recap after a turn that changed files or had a command fail (the files with their + and − lines, and the failed commands); a master switch and Command Center toggles. Prompts and replies stay Paseo's own, with Fork and Copy.
- **Chat look:** exact text sizes (9–20 px) and code sizes (10–22 px) for Morphise's rows, more accent presets, the system font or a reading style (Document, Compact, Terminal) for Paseo's replies, made with CSS so Paseo still draws them with Fork and Copy. The turn recap opens to the model, thinking level, time and tokens Paseo reported. Every settings preview has a Desktop / Phone switch.
- **Hover previews and tables (desktop and web, off by default):** rest on a folded row to read its content in a floating preview (delay, wrap, line numbers, shading); copy Paseo's tables as Markdown and pick cells to copy or add to the message box.
- **Messages:** a bar over text you select in a chat (desktop and web, from Quote): Quote it into the message box, Reply to it in place (a reply sent while the agent works waits for the turn to end, and is not sent, with a note saying why, if the turn stops for permission, fails or runs too long), ask a Side chat beside the chat, Copy it as text or Markdown, or Bookmark it to the Workbench. Thumbnails for replies that are only images, image stacks that spread into a row, diagrams by Paseo's mermaid or Pele, and styles for quotes, tables, code, headings, lists and callouts.
- **Commands** (runner from Shell Yeah, see NOTICE.md): `/run` followed by a command runs it as you, in that chat's folder, on every platform; on desktop and web a Run button beside Paseo's Copy code does the same for a reply's shell code blocks (on by default; Settings, Messages, Commands), and its live output opens under the block, as in Claude Desktop, with icon buttons for Stop, Copy, In chat and Close; click its output (or the keyboard button) to type into a command that asks for input, such as a name or a password, and Esc to stop typing. Paseo's own keyboard shortcuts still come first: on Windows and Linux that includes Ctrl keys such as Ctrl+W, Ctrl+D and Ctrl+L, so those reach Paseo, not the command (on a Mac, Ctrl keys reach the command). Settings choose where the output shows (under the block or only in the card), how many lines the panel shows, icons or icons with labels, and whether the card stays as one line or hides while the panel shows. Each run is also a card in the chat with live output, Stop and typing into it (2FA codes, passwords), then the exit code, Copy, Rerun and Send to agent; phones and other windows show the card. Commands that need administrator rights, delete files, discard changes, force-push, run a script from the internet, hide characters, or are long or padded enough to hide part of themselves (a line over 200 characters, a long run of spaces, more than 40 lines) ask first, and a confirm covers only the exact text it showed. If the daemon stops answering, the card and the panel say so after three tries. When a command run without a terminal exits, background jobs it left behind are stopped with it.
- **Restyle Paseo (experimental, off by default):** Chat Polish's design for Paseo's own message box, cards, menus, tool groups and replies; a flat or floating window; seven working indicators; Untitled UI or Hugeicons icons; a provider rail in the model picker and a clearer context card; ⌥⌘↑ and ⌥⌘↓ to jump between your prompts.
- **Pages (on unless turned off; Settings, Chat, HTML pages):** agents draw an interactive page in the chat without being asked whenever it is clearer than text (options to choose between side by side, numbers, plans and structures, UI mock-ups, reports and reviews), or when you ask, like Claude's inline visuals: charts, tables, comparisons, dashboards, diagrams, mock-ups. Short answers stay text. Built-in helpers keep them tidy and in your theme: `Morphise.chart` (bar, line, area, donut, sparkline, laid out so labels never overlap), sortable and filterable tables, picture galleries; the agent reads the rules for a kind of page from `html_guide` only when it draws one. A page can update an earlier one (the earlier shows "Updated below"). A click in a page can put a follow-up into your message box (it never sends). Each page has Save (to the Workbench's Bookmarks, kept on the daemon while the bookmark lasts), Download HTML, Download SVG, Open in browser, Copy HTML and full screen. An optional headless browser checks each page's layout first. A page shows, previews and checks only pictures inside its agent's working folder. New chats get the tools, and existing Claude, Codex and OpenCode chats when their session reopens (for example after a daemon restart).
- **Show in Paseo (on by default; Settings, Chat):** your agents get a `show_in_paseo` tool that brings something to the front of the Paseo window you used last: a chat, a terminal, a workspace, the Workbench or Dispatch. It can also put text in a chat's empty message box for you to read and send (never a slash command, and never sent), or pin and unpin a workspace. An agent can leave the chat or workspace out to mean its own. Only your own chats can use it, not sub-agents or background helpers, at most ten times a minute each, and while you are typing in a window (on a phone, while its keyboard is up) it changes nothing there. Terminals and workspaces need Morphise's sidebar view selected in Paseo.
- **Theme:** a light or dark palette from eight colours (or one of eleven ready-made ones, among them VS Code Dark 2026, JetBrains Dark and Cursor Dark), with contrast warnings and an optional sidebar colour, listed under Settings, Appearance.
- **Buttons:** sidebar header and footer rows, workspace header buttons or menus, your own pills above the message box, and message box controls (a button, an on/off switch saved on the chat, or a model, mode or thinking picker).
- **Commands:** slash commands, Command Center items and New workspace presets.
- **Style layer (unsupported, off by default):** hide built-in parts by their test id and add your own CSS. Desktop and browser only; any Paseo update can rename the ids it relies on.

Buttons, rows, commands and controls run one of a small set of actions: open a link, insert or replace text in the message box, set the model, mode or thinking level, or open Morphise's settings. Morphise has no action that runs commands or writes files.

## Tasks and reminders

- **Board:** open "Tasks" in the sidebar, the Tasks panel in a workspace (only that workspace's cards), or "Open tasks" in the Command Center.
  - Columns: name, colour, order, a work in progress limit, and which one is Done, under Customise.
  - Cards: title, description, priority P1 to P4, labels, due date, reminder, checklist, link, workspace, and the chat they belong to ("Insert into chat" puts the card in its message box). Drag a card to move it, to another column or to a new place in its own (with the mouse on a computer, after a long press on a phone); the board scrolls when a card is held near its edge. Screen readers move a card a column at a time from its actions.
  - Workspaces: pick a card's workspace in its editor (the arrow beside it saves the card and opens that workspace), or use "Attach tasks" in a workspace's Tasks panel to bring existing tasks in. The main board shows each card's workspace.
  - Quick add: `Fix login p1 @bug #review due:fri tomorrow 9am`. The preview under the box shows what each part became.
  - Filter, and Display (order, rows by priority, label or workspace, card size). Active filters show as removable tags, and a column says how many cards a filter hides.
  - Add a card straight into a column with its plus button: type a title, press Enter, keep going.
  - Today lists reminders due, overdue cards, cards due today and reminders later today. Archived lists archived cards; Customise can archive Done cards after some days.
  - Automations: when a linked chat needs permission, fails or finishes, move its card to a column; when a card enters Done, clear its reminder. They run while any Paseo app is open.
- **Remind me:** every reminder belongs to a card. "Remind me" on a chat sets the reminder on that chat's follow-up card, creating it in the first column if needed.
  - Open the picker from the workspace header, the alarm button or a long press on a chat row in Morphise's sidebar view, or a card.
  - Choose a preset (yours, on the Sidebar tab), "This evening", "Tomorrow morning" or "Next week"; each shows the time it lands on. Or open "Custom time…" and type `45m`, `17:30`, `5pm`, `tomorrow 9am` or `fri 10:00`. Type a note for when you come back before picking the time; a time sets the reminder at once. Reminders can be 1 minute to 7 days ahead.
  - `/remind <time>` and `/remind clear` in a chat; `/task <quick add>` adds a card linked to the chat; the Command Center has the presets and "Clear this chat's reminder".
  - When a reminder is due: "Tasks" in the sidebar shows how many are due; the card is listed under Reminders at the top of the sidebar view (tap it to open the card in Workbench, Tasks; a reminder on a chat also has a button for that chat); open apps chime, show a toast and, if you allowed it, a desktop notification; a row appears in the linked chat with Done, +15m, +1h and Move to Done.
  - +15m and +1h on a reminder that is not due yet push it later. Reminders on Done or archived cards are paused.

## Notes and prompts

- **Chat notes:** a Notes panel beside any chat (or "Open this chat's notes" in the Command Center), saved on the chat.
- **Prompts:** saved prompts shared by every layout; pick one from the Prompts box in any message box to insert it.

## Setup and limits

Requires Paseo 0.16.0-beta.1 or later, on both the daemon and the app.

- Session stats and "Search conversations" read the chats' log files on the daemon's computer: `~/.claude/projects` (or `CLAUDE_CONFIG_DIR`) and `~/.codex/sessions` (or `CODEX_HOME`). They never change those files, and they read a chat through Paseo's stored record only, so a finished agent is not started again. A log line that is not valid JSON makes the reading say so instead of showing smaller numbers.
- Settings are stored on the daemon, so every app connected to that host shares them. They are plain JSON, not a secret store. Which groups are folded and which statuses are filtered are kept per device.
- The task board is one settings document on the daemon, shared by every app; changes from several apps at once are merged. Notes are stored on the chat, so they go when the chat does.
- Paseo gives plugins no notification or "unread" control, so a reminder cannot make Paseo itself ring; Morphise shows it in its own row, list, view, chime and notification. A reminder row in the chat is written by the daemon; if no app is connected at the time, it is written once one connects.
- Sorting, filtering and reminders in the list apply to Morphise's own sidebar view; plugins cannot reorder Paseo's built-in list or add items to its right-click menus, so "Remind me" sits in the workspace header, /remind, and Morphise's own rows.
- Paseo's Mark as unread, Manual (drag) order and Open project settings have no plugin API, so Morphise's view cannot offer them. Remove project has none either, so under "Your groups" it runs Paseo's command line on the daemon (`paseo project delete`), only after checking that daemon lists the project and after a confirm: it deletes the project and archives its workspaces, worktrees Paseo made go with their ignored files, the project folder stays, and it cannot be undone. Any app connected to the daemon can do it, as with Paseo's own remove. Its hover card opens under the row, because a plugin cannot draw beside the sidebar.
- With an order other than Manual (Display), dragging a card changes only its column: its place in the column follows the order.
- Actions from header buttons, sidebar rows and the Command Center act on the focused chat's message box.
- If Paseo rejects part of the settings, such as an unknown icon name, that part is skipped, the rest still applies, and the Advanced tab lists what was not applied and why.
- Ids starting with `morphise-` and the `/remind`, `/task`, `/bookmark` and `/run` commands are reserved for Morphise's own items; a custom command with one of those names is renamed with `-custom` added.
- CSS in the style layer can load remote resources like any stylesheet.
- The daemon needs npm: Morphise installs two packages there, `pele` (diagrams) and `sharp` (thumbnails, with its WebAssembly build for Paseo's macOS app, which refuses native code signed by another team), each loaded only when its option is used.
- Network: opening Settings, General checks for a Morphise update, and Update installs exactly the version that check showed. Otherwise only for options you turn on: an icon set is downloaded from npm (and checked against a pinned hash) the first time you pick it, and the headless browser (about 100 MB) when you press Download. HTML pages run a local page server on 127.0.0.1, and agents created while the option is on keep that tool in their settings.
- HTML pages give each agent its own token for the page tools, saved in its settings; the daemon keeps only a hash of it with the agent's working folder (`agent-folders.json` in Morphise's pages cache), and the tools open a page's local pictures only inside that folder. Going back to an earlier Morphise leaves agents created since without the page tools until you update again, and lets the tools read pictures from anywhere on the machine again.
- While the steps card is on, Claude agents start with Claude Code's task-list tools (`CLAUDE_CODE_ENABLE_TODO_TOOLS=1`), and each new Claude chat gets one added instruction to keep a task list with them (Paseo appends it to Claude Code's own instructions). Both use a little of the agent's context, and chats started before the steps card was on get only the tools.
- Show in Paseo reaches agents through Paseo's MCP tools, so Paseo's `daemon.mcp.injectIntoAgents` must be on. Paseo fixes a chat's tools when its session opens: turning the switch on reaches new chats and chats whose session reopens (daemon restart or plugin reload); turning it off refuses at once. Each use is a `[morphise] show_in_paseo` line in the daemon log. A draft goes in only when the box looks empty, but Paseo can report a box as empty for a moment after you type; the draft is then added beside your text and never erases it (text selected in that box at that instant is replaced).
- The selection bar, restyle and image stacks work through Paseo's page structure on desktop and web; a Paseo update can break parts of them. Turn off the separate Quote or Chat Polish plugins if you have them, or you get two bars and two sets of rows.
- Commands from `/run` and the Run buttons run on the daemon's computer as you, in the shell the code block names (```bash in bash, ```sh in sh, ```zsh in zsh; the daemon looks only in /opt/homebrew/bin, /usr/local/bin, /bin and /usr/bin, never on PATH, and says so when it isn't installed) or else your login shell, as `/run` always does (Settings, Commands, can make every block use the login shell; Windows always uses PowerShell), with your permissions, and only when you press Run or send `/run`; nothing an agent writes starts one. They run in the chat's own folder, up to eight at once; output is kept a week (at most 100 MB) under `~/.local/state/morphise/runs`, and archiving a chat stops its commands and deletes their output. The Run buttons read Paseo's page on desktop and web, so a Paseo update can hide them; `/run` keeps working. `/run` works in a chat that has replied at least once: Paseo gives a plugin's command no chat in a brand-new one, so there the text goes to the agent as a normal message. Shell Yeah can be installed beside Morphise: its command is `/sh`.
